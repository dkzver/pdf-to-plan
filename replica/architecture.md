# Архитектура: свой редактор планировки (пересборка ядра Sweet Home 3D)

Источник: `replica/recon.md` + `replica/features.csv`. Область: план → мебель → 3D → файл.

## Стек

| слой | выбор | почему |
| --- | --- | --- |
| веб | Next.js 15 (App Router) + TypeScript | один деплой на редактор, лендинг и страницу шаринга; знакомый стек, дешёвый хостинг |
| стили | Tailwind + токены из `replica-design` | токены задаются один раз и живут в коде, а не в макете |
| план 2D | Canvas 2D + собственный слой геометрии и привязок | CAD-привязки, размерные линии и хит-тест проще держать на своём рендере, чем бороться с DOM/SVG на тысячах объектов |
| 3D | three.js (WebGL2) + GLTF-мебель | открытый, без лицензий, грузит glTF-модели и даёт тени/свет из коробки |
| состояние | Zustand + immer, undo через стек команд | один документ дома как источник истины; отмена и повтор по командам, а не по снапшотам всего состояния |
| геометрия | своя, единицы — сантиметры (целые) | никаких ошибок плавающей точки в размерах и привязках; экспорт в мм/дюймы на границе |
| файлы | JSON `.plan.json` со Zod-схемой и версией формата | читаемый дифф, миграции по `version`, никакой привязки к чужому формату |
| хранение | IndexedDB (idb) для автосохранения + File System Access API, где есть | продукт локальный по своей природе: без аккаунта и без сети работает |
| деплой | Vercel | статика + edge-функции для шаринга, если понадобится |
| база | нет в v1; Postgres (Supabase) для галереи и шаринга в v2 | не тащим сервер туда, где хватает файла на диске |
| авторизация | нет в v1; Supabase Auth при появлении шаринга | не заставляем регистрироваться, чтобы нарисовать комнату |
| платежи | нет в v1 | монетизацию определит отдельный шаг, а не догадка |
| почта | нет в v1; Resend при появлении аккаунтов | — |
| фоновые задачи | нет в v1; Vercel Cron для превью-миниатюр галереи | — |

Отклонение от дефолта пака: база и авторизация отложены. Причина — у оригинала нет аккаунтов, а платить за пустой Postgres на старте незачем. Схема для v2 лежит в `replica/schema.sql`, чтобы шаринг не потребовал переписывания документа.

## Схема

Документ (`Home`) — источник истины, живёт в JSON и в памяти. Таблиц в v1: 0. Таблиц под v2-шаринг: 4. Правила доступа: RLS на Supabase, владелец — `owner_id`.

```ts
// src/lib/home/schema.ts (Zod, version 1)
Home        { version, id, name, unit: 'cm'|'inch', grid: {step, visible},
              walls: Wall[], rooms: Room[], furniture: Furniture[],
              levels: Level[], background?: {imageRef, scale, angle},
              environment: {sky, groundColor, light} }
Wall        { id, a: Pt, b: Pt, thickness, height, baseboard, levelId,
              left?: Finish, right?: Finish }
Room        { id, name, polygon: Pt[], levelId, floor?: Finish, ceiling?: Finish,
              ceilingVisible: boolean }
Furniture   { id, name, catalogId?, modelRef?, x, y, elevation, angle, w, d, h,
              visible, mirrored, levelId, materials: MaterialOverride[] }
Level       { id, name, elevation, height, visible }
Finish      { color?: string, textureId?: string, shininess?: number }
MaterialOverride { mesh: string, color?, textureId?, shininess? }
```

Жёсткие ограничения: `w,d,h > 0`; угол нормализуется в `[0,360)`; стены с общей точкой считаются соединёнными; комната не может ссылаться на несуществующий уровень (проверка при загрузке файла, а не только в UI).
SQL для v2 — `replica/schema.sql`: `homes`, `home_versions`, `catalog_items`, `textures`.

## API и маршруты

Ядро работает в браузере, серверных вызовов на каждый чих нет.

| метод, путь | что делает | кто | вход | выход | поток |
| --- | --- | --- | --- | --- | --- |
| `GET /` | редактор, пустой дом или последний из IndexedDB | все | — | HTML + клиент | F01–F08 |
| `GET /share/[token]` | просмотр дома только для чтения (v2) | все со ссылкой | token | HTML + read-only 3D | F03 |
| `POST /api/homes` | сохранить дом в облако (v2) | владелец | JSON дома | id, url | F08 |
| `PUT /api/homes/[id]` | обновить дом (v2), версия в `home_versions` | владелец | JSON дома | 200 | F08 |
| `GET /api/homes/[id]/versions` | история версий (v2) | владелец | — | список | F08 |
| `POST /api/catalog/import` | принять glTF/OBJ и вернуть метаданные (v2) | владелец | файл | piece | F07 |

Экспорт и печать — на клиенте: PNG через `canvas.toBlob`, SVG через собственный эмиттер, PDF через `pdf-lib` с масштабом 1:50/1:100 и разбиением на страницы, OBJ/GLB через three.js `GLTFExporter`. Вебхуков и фоновых задач в v1 нет.

## Что кусается

- **Точность и привязки.** Размеры в целых сантиметрах, привязка считается в экранных пикселях и переводится в см на текущем масштабе; иначе на зуме 400% объекты «прыгают».
- **Два представления.** План и 3D не должны жить отдельными моделями: 3D пересобирается из документа, а во время перетаскивания обновляются только трансформы, полная пересборка — по завершении жеста.
- **Проёмы в стенах.** Двери и окна вырезаются сегментацией стены на участки (до/после проёма + перемычка), без CSG. Иначе геометрия дешёвая, а баги вечные.
- **Материалы по частям модели.** У glTF меша имена не нормализованы: сопоставление по имени с фолбэком на «всю модель», а не падение.
- **Undo/redo при перетаскивании.** Один жест — одна команда: коалесцировать промежуточные `move` в стеке, иначе отмена идёт по пикселю.
- **Производительность.** Инстансинг мебели, ленивая загрузка моделей, рендер по требованию; 200 предметов на плане должны оставаться отзывчивыми.
- **Печать.** Масштаб и тайлинг страниц: план 12×9 м в 1:50 не влезает на A4 — нужны направляющие разрезов и колонтитулы.
- **Формат.** Свой `.plan.json` + миграции по версии; чужой `.sh3d` в v1 не читаем и не обещаем.
- **Офлайн.** PWA-кэш и системные шрифты; ни одной сетевой зависимости в основном сценарии.
- **Часовые пояса.** Не применимо; для солнечного света — только дата/время/широта как параметры рендера.

## Порядок сборки

1. **Вертикальный срез** (экраны S01, S02, S04, S05, S06): пустой дом → четыре стены → перетащить стул → аэро-3D → автосохранение в IndexedDB → сохранить файл и открыть его снова. Таблиц нет, маршрут один — `GET /`. Доказывает стек и связку план ↔ 3D.
2. **Must-haves по областям:** План (комнаты, размерные линии, сетка/магнетизм, масштаб, правка стен) → Мебель (категории, поиск, материалы, список) → 3D (виртуальный визит) → Файлы (отмена/повтор, открытие/сохранение).
3. **Should-haves:** отделка пола/потолка, уровни, настройки 3D, рендер фото, PDF/PNG/SVG, импорт мебели, подложка-скан, настройки.
4. **Could-haves:** видео-облёт, солнце по дате, экспорт OBJ.
5. **Правки от `/replica-entrepreneur`** — после того как он прочтёт отзывы.

Ближайший шаг: `/replica-design` — токены, типографика, компоненты и спека плавающих панелей по скриншотам из `replica/screens/`.
